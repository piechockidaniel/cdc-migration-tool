# 2. The web UI

The UI is a single-page application served at `/`. It runs without any build step or CDN
(all libraries are vendored), so it works in an air-gapped network. Light and dark theme
(moon/sun button), live status pills in the top bar (WebSocket feed, health, active alerts).


| Page               | What you can do                                                                                                                                                                                                                                                              |
|--------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Dashboard**      | KPIs (pipelines, applied/failed 24 h, success rate, worst lag, DLQ size, alerts, snapshots), throughput / lag / queue charts (server-side history survives reloads), pipeline table, active alerts, top failure patterns, live event feed (WebSocket), recent audit          |
| **Connections**    | engine-aware form (SQL Server, PostgreSQL, MariaDB/MySQL, MongoDB, Oracle, SQLite destination, Demo), secret references, test, **CDC prerequisites** with fix hints and one-click enable/disable capture, table & column browser, Service Broker push-mode script            |
| **Mappings**       | table/SQL mappings, browse source & destination, **auto-map** (name match + PK→PK), column grid (transformation, default, ignore, auto-generate), key columns, sync flags, validate, data-quality verify, version history, duplicate, snapshot shortcut                      |
| **Pipelines**      | define (source, destination, mappings, initial position, insert mode, batching, auto-start), start/pause/resume/stop, live counters, positions, **health facts** (rule-engine input), reset positions; tab with 1.x working sets (now referencing library connections by id) |
| **Snapshots**      | create chunked jobs (key, range filter, chunk/adaptive sizing, rate cap, maintenance window), progress/ETA, pause/resume/cancel/reset, poison rows counted and parked in the DLQ                                                                                             |
| **Alerts & Rules** | active/resolved alerts with facts, rule sets on/off, rule editor with **validate against current facts**, channels (webhook, e-mail) + test                                                                                                                                  |
| **Failures**       | patterns with category, share, suggestion and **Apply** (set default / upsert / key columns / transformation / disable mapping), replay through a running pipeline, DLQ table with payload and bulk actions                                                                  |
| **Audit trail**    | filter by category/severity/table/time, text search, CSV export                                                                                                                                                                                                              |
| **Metrics**        | counters, p95 latencies, charts, link to the Prometheus endpoint                                                                                                                                                                                                             |
| **Settings**       | instance info, event-bus stats, retention purge, export/import of the whole configuration                                                                                                                                                                                    |

## Context help and the guided tour

* Every page starts with a **hint box** explaining what the page is for, where it sits in the
  flow (Connections → Mappings → Pipelines → Snapshots → observe) and the traps to avoid
  (e.g. "start the pipeline before the snapshot"). The editor dialogs (connection, mapping,
  pipeline, snapshot job, alert rule) carry a shorter hint about their fields. Dismiss a hint
  with its ✕; it stays hidden in this browser until you choose **? → Show page hints again**.
* The **guided tour** (? menu → *Take the guided tour*) walks through the eleven stations of
  the flow with a spotlight on the relevant button or tab, changing pages as it goes. Use
  `Next`/`Back`, the arrow keys or the dots; `Esc` or *Skip tour* closes it. It starts by itself
  the first time the UI is opened on an **empty instance** (no connections) and never again
  once finished or skipped. Append `?notour` to the URL hash (`/#/dashboard?notour`) for kiosk
  screens or automation.
* The ? menu also links to this user guide (served at `/app-docs/...`) and the OpenAPI page.

Old bookmarks redirect: `/admin` → `#/connections`, `/operations` → `#/pipelines`,
`/monitoring` → `#/dashboard`. The 1.x pages (visual workflow designer,
multi-source builder, ingestion patterns) remain available under `/legacy/…`.

## Browser tests (developers)

`tests/ui` contains a headless-Chromium harness that needs only npm
(`@sparticuz/chromium` ships the browser inside the package):

```
cd tests/ui && npm install
CDCSYNC_URL=http://localhost:8000 npm run smoke        # every page renders, no console errors
DEST_PATH=/tmp/dest.sqlite3 npm run e2e               # full demo scenario (see e2e.mjs header)
npm run tour                                          # guided tour: every step finds its anchor; hints dismiss/reset
```

Screenshots of the e2e run are in `docs/screenshots/` (`guided-tour.png` shows the tour). Frontend internals: [developer guide](../developer-guide/05-frontend.md).
